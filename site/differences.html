How it differs from Xash3D FWGS

The engine core is still Xash3D FWGS. The port adds a platform layer, a renderer, an asset pipeline and tools around it.

Still upstream

The client and server, networking, physics, the console, save and load, and the GoldSrc compatibility layer. The version is upstream's (0.21), and other targets keep upstream's name.

The Xbox build reports itself as Xash3D FWGS-XBOX 0.21 (xbox-i386 build N). The OS reads xbox because nxdk targets i386-pc-win32 and would otherwise say win32.

The divergence ledger

Every deliberate deviation from upstream is recorded the same day it is written, with what changed, why, in what form (a new file, an #ifdef, a replacement), the merge risk, and what it would take to remove it. The point is that merging upstream stays possible. The ledger is docs/r3d/divergences.md; the plan behind the work is docs/r3d/fork-plan.md.

Preferred forms, cheapest to most expensive to maintain: a new file in our own directory; a new file inside an upstream directory; #ifdef XASH_XBOX around upstream code; rewriting an upstream function (needs explicit justification). Changing behaviour with no #ifdef is forbidden unless it is a genuine upstream bug, in which case the patch goes upstream first.
