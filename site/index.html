Xash3D-FWGS-XBOX

Half-Life on a real original Xbox (2001), through a port of the GoldSrc-compatible Xash3D FWGS engine built against the open-source nxdk homebrew SDK.

Status. Half-Life plays on hardware: the engine, the NV2A renderer, the menu, saves, hardware audio and the offline asset pipeline work, and the first campaign maps run on a console. It is work in progress. Frame times are measured, not yet where we want them, and Opposing Force and Blue Shift are not packaged yet.

Roadmap

  1. The whole campaign playable at 720p We are here
    Today the first campaign maps run on a console, and a 45-minute Office Complex route has been recorded at 720p. The milestone is Half-Life from start to finish at 720p, which is what the 60 fps work is for.
  2. Multiplayer. The Xbox build is compiled without networking today (no sockets), so this starts with the network layer, then the multiplayer screens already drawn in the design mocks (system link, internet games, host game, direct connect, player profile) and the on-screen keyboard they share.
  3. Split screen. Two players on one console. The menu design has the screen, but the engine has no second local client at all: it would need a second client state, a second view, input from a second controller port and a listen server hosting both, on a 733 MHz CPU. The project plan keeps it out of the multiplayer milestone until a second viewport has been measured.
  4. Opposing Force. Its game libraries have a fork and the packager lists it, but it is not packaged yet.
  5. Blue Shift. The same: a game-library fork exists and the packager lists it, but it is not packaged yet.

What makes this port different from a recompile

  • A 64 MB budget shared with the GPU. The memory ceiling is enforced offline, by the asset baker, not discovered at runtime. A map that does not fit breaks the build, not the console.
  • An offline asset pipeline. Maps, textures and sounds are compiled ahead of time into .mpak archives with per-map texture atlases, DXT compression and packed lightmaps, so the engine never parses a WAD on the console.
  • The console's own hardware. A renderer for the NV2A GPU (pushbuffer, register combiners, vertex programs) and audio on the console's audio chip.
  • Menus made for a controller. Gamepad navigation, a button legend on every screen, a pause menu, and layouts for 4:3, 16:9 and 720p. See the menus.
  • A target and a way to measure it. 720p at 60 fps, with a frame-time recorder on the console and a report on your PC. See progress.

You need your own game

This project contains no Valve assets. Running Half-Life needs your own legally obtained copy (Steam). The baker reads your install and produces the archives locally; they are not redistributable.

Code signing policy

Free code signing provided by SignPath.io, certificate by SignPath Foundation.

Status: the Windows packager is not signed yet. The application to SignPath Foundation is in progress, and until it is approved Windows will warn about an unknown publisher: check the file against SHA256SUMS.txt in the release.

  • What is signed: the Windows packager exe of each release (the packager and the asset baker). It is built by a GitHub Actions workflow from this repository's source, and nothing else is signed. The Xbox build (default.xbe) is data beside the exe, not a Windows program.
  • Roles: committers and reviewers: mathiasdbo, the project owner, who also approves every signing request. Members use multi-factor authentication on GitHub and SignPath.
  • Privacy policy: this program will not transfer any information to other networked systems unless specifically requested by the user or the person installing or operating it. The packager connects only to the Xbox whose address you give it, or finds one when you press Find my Xbox, which scans your own network.
