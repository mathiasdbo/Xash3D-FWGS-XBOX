Progress

Where the performance work stands: the target, what has been measured and on what, what has landed, and what is still open.

Next milestones

  1. The whole campaign playable at 720p We are here
    Today the first campaign maps run on a console, and a 45-minute Office Complex route has been recorded at 720p. The milestone is Half-Life from start to finish at 720p, which is what the 60 fps work is for.
  2. Multiplayer. The Xbox build is compiled without networking today (no sockets), so this starts with the network layer, then the multiplayer screens already drawn in the design mocks (system link, internet games, host game, direct connect, player profile) and the on-screen keyboard they share.
  3. Split screen. Two players on one console. The menu design has the screen, but the engine has no second local client at all: it would need a second client state, a second view, input from a second controller port and a listen server hosting both, on a 733 MHz CPU. The project plan keeps it out of the multiplayer milestone until a second viewport has been measured.
  4. Opposing Force. Its game libraries have a fork and the packager lists it, but it is not packaged yet.
  5. Blue Shift. The same: a game-library fork exists and the packager lists it, but it is not packaged yet.

The target: 720p at 60 fps

The goal is Half-Life at 1280x720 and 60 frames per second, which gives each frame 16.7 ms for the CPU and the GPU together. The recorder draws the 16.7 ms and 33.3 ms lines and reports the share of frames over each.

  • 720p is a real output mode today: r3d_vid_mode 1, or the Display menu, with anisotropic filtering and anti-aliasing. 4x anti-aliasing at 720p was judged out for memory (about 25 MiB more).
  • No per-map frame-rate goals are written down yet. The performance review asks for exit criteria with a number for each phase, which is the next thing to settle.
Read the numbers with care. Console figures are from a real Xbox. Figures marked emulator come from xemu on a PC: good for comparing one change against another, not a Pentium III timing. The performance review itself says most per-change numbers have not been repeated on the console.

Where it stands on the console

  • Original baseline: the owner's route averaged 44 fps on a real console, with four maps near 30. The same route in the emulator held 60 on almost every map, because the emulator is not the console.
  • 720p, 45-minute Office Complex route: frames over 33 ms went from about 5% to 1-3% on c1a2, and from 4.5% to 1% on c1a2a.
  • Still open: the Office Complex still has 1-3% of frames over 33 ms. The slowest maps found are c1a1b (water), c1a0c and c1a0e (beams). Level-load stalls remain, and many changes below still say "console numbers to be recorded".

How frames are measured

The frame-time recorder has grown with the work. It began as a ring of frame times written to the drive, an overlay and a report. Since then it gained 20 per-frame renderer counters, a flag for load frames and a stalls table, then CPU spans per subsystem (scene, particles, beams, mixer, network, server game, player movement, client entities, saves, menu, music, load stages), labelled segments per map, and report commands to compare two sessions or fetch them from the console or the emulator. The recorder cannot time the GPU itself (the SDK has no GPU timestamp), so it records how long the CPU waited for it.

Stalls found this way: one 350-1000 ms spike per map turned out to be mostly level changes, and six longer ones were autosaves.

Next

  • Repeat the emulator-only results on the console and write down the numbers.
  • Skinning limit: about 50 bones fit in the GPU's vertex-program registers, and the game allows up to 128.
  • The baker's next phase: draw lists per cluster and material, bone partitioning, 16-bit lightmaps, ordering that suits the GPU's vertex cache.
  • Lightstyles: the baker bakes style 0 only, so switching and flickering lights are not baked yet.
  • Threaded save and load I/O. SSE only once a profile on hardware says it pays.
  • Per-map frame-rate goals, then the 60 fps work on the maps that miss them.
