Console settings

The packager's second tab reads and changes what an install runs with, on the console over FTP or in an exported folder on your PC.

How it works

The engine runs config.cfg (the in-game menu's) and then every userconfig.d/*.cfg in name order; later files win. The tab writes one file of its own, userconfig.d/50-packager.cfg, so it overrides the menu only for what it sets. A setting left on "(don't set)" is not written and the menu keeps deciding it.

  • Find my Xbox fills in the address, looks through the games folders for installs of this game and reads the one it finds.
  • What the console runs with shows each setting's value and the file it comes from, and warns when a later file overrides yours or loads a map on every start.
  • Each userconfig.d file has a tick: it renames the file to or from .off, which is how the engine skips it. Nothing is overwritten; saving an edited file keeps the old one as .before-packager.
  • Presets: Sharp (720p, 8x anisotropy), Measure (recorder on, label, memory report) and Clear all.

Anti-aliasing (nv2a_r_aa)

This is the GPU's own multisampling. The 3D view is drawn into a larger surface and scaled down to the screen in one pass; the HUD, console and menus are drawn afterwards at the screen's own resolution, so they stay sharp. In the menu the same choice is Options, Display, Anti-aliasing (Off, 2x, Quincunx, 4x).

ValueMenu nameWhat it isExtra memory at 480p
0OffThe 3D view is drawn straight into the screen. The default.none
12x2x MSAA: two samples per pixel, resolved with a bilinear filter between them.about 2.3 MiB for each of the two surfaces (colour and depth)
2QuincunxQAA: the same two samples as 2x, resolved with the GPU's Quincunx filter, which blends in neighbouring pixels as well. Softer than 2x, at the same cost.the same as 2x
34x4x MSAA: a 2x2 block of samples per pixel, resolved at the block's centre. The smoothest edges, and the most memory and fill cost.about 4.7 MiB for each of the two surfaces
  • Memory is taken between frames and given back before a map's own buffers are made. At 720p the surfaces are larger: 4x there needs about 25 MiB more, which is why it was judged out as a default.
  • If the surfaces cannot be had, the engine keeps drawing without anti-aliasing, and does not ask again until you change the setting or the map.
  • Quincunx on the console is not yet confirmed by a hardware check: the emulator draws that filter as a plain blur, so judge it on a console.
  • Transparent edges (decals, sprites) alias more than solid edges under MSAA.

Stick drift: the view turns by itself

Original Xbox pads rest well off centre: a right stick that nobody is touching can read about a fifth of the way over. Below its dead zone the engine takes that for input and the view turns on its own. The Xbox build's default dead zone is 8689 for this reason. PC Half-Life's config.cfg sets all four dead zones to 0, and the packager before v0.1.2 copied it to the console, where it ran on the first start and was then saved.

If that happened to your install, the Console settings tab says so under What the console runs with (too small for an Xbox pad). Read the install, press the Fix stick drift preset, and Write settings: it writes the four dead zones as 8689 to userconfig.d/50-packager.cfg, which runs after the saved config.cfg on every start. The Controller group lets you choose other values. Screenshots, and two other ways to fix it, are on the Troubleshooting page.

Audio options (backend, rate, hardware audio) and developer switches (GPU skinning, culling) are in the tab too; developer settings are behind a tick. Video output, sound backend, rate and hardware audio are read at boot, so a change shows at the next start of the game.
